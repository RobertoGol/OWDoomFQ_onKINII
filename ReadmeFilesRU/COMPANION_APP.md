# 📱 Спецификация мобильного приложения-компаньона (COMPANION_APP.md)

Статус: **целевой дизайн, не реализованная подсистема**. Общая сверка: [PROJECT_STATUS.md](./PROJECT_STATUS.md) / [PROJECT_STATUS.v2](./PROJECT_STATUS.v2); размеры схем: [SERIALIZATION_SPEC.md](./SERIALIZATION_SPEC.md) / [SERIALIZATION_SPEC.v2](./SERIALIZATION_SPEC.v2) (сырые правки не считаются утвержденными без записи в `sql.core` и `memory.ctos`).

Настоящий документ определяет архитектуру, логику интерфейсов и протоколы синхронизации мобильного приложения-компаньона. Приложение объединяет функции **защищенного мессенджера (гильд-чат, группы, друзья)** и **панели стратегического менеджмента базы** (в стиле *State of Decay 2* и *Fallout 76* Pip-Boy).

Мобильный клиент работает на базе кроссплатформенной визуальной оболочки из папки `View/` под управлением мобильной версии изолированного рантайма **KINII (void.run)** для операционных систем Android 10–15 (архитектура ARM64).

---

## 🏗️ 1. Архитектура мобильного узла (Mobile Node Architecture)

Мобильное приложение не является просто веб-клиентом. Оно запускает внутри себя полноценный облегченный слой ядра KINII, обеспечивающий криптографическую защиту и прямую обработку сетевых прерываний.

```text
        ┌────────────────────────────────────────────────────────┐
        │               ВИЗУАЛЬНЫЙ СЛОЙ (View/)                  │
        │  Интерфейсы чата, Профили, Тактическая карта ресурсов  │
        └───────────────────────────┬────────────────────────────┘
                                    │ (Внутренний RPC)
                                    ▼
        ┌────────────────────────────────────────────────────────┐
        │               МОБИЛЬНЫЙ РАНТАЙМ (void.run)             │
        │       Управление потоками, Очередь сообщений, E2EE     │
        ├───────────────────────────┼────────────────────────────┤
        │ 📄 memory.ctos (Ghost-RAM)│ 📄 sql.core (HiddenVault)  │
        └───────────────────────────┴────────────────────────────┘
```

### 1.1 Системные особенности для Android 10–15 (ARM64)
* **Адаптация под BIG.LITTLE:** Мобильный рантайм автоматически переносит тяжелые криптографические операции на производительные ядра (BIG), а фоновое ожидание push-уведомлений и синхронизацию чата удерживает на энергоэффективных ядрах (LITTLE) для сохранения заряда батареи.
* **Изоляция памяти:** Для предотвращения перехвата сообщений вредоносным ПО или клавиатурными шпионами (Keyloggers) на Android, текстовые буферы чата рендерятся через защищенные области Ghost-RAM, контролируемые файлом `memory.ctos`.

## 💬 2. Подсистема Мессенджера и Сквозного Шифрования (E2EE)

Мессенджер полностью дублирует игровой чат. Игрок на смартфоне может общаться с согильдийцами, находящимися внутри игры UZDoom.

### 2.1 Протокол обмена сообщениями
1. **Инициализация сессии:** При первом запуске приложение считывает `MASTER_HWID` смартфона (через `main.vc`) и генерирует пару ключей (публичный/приватный) на базе алгоритма Ed25519 (в черновиках указан как `Ed25514`). Приватный ключ никогда не покидает Ghost-RAM устройства.
2. **Маршрутизация трафика:** Сообщения передаются через центральный хаб (`deploy_hub.vc`), используя протокол зашифрованных сырых сокетов.
3. **Сквозное шифрование (End-to-End Encryption):** Каждое приватное сообщение шифруется на стороне отправителя симметричным ключом сессии (AES-GCM-256). Бэкенд-сервер видит только зашифрованный бинарный шум и не имеет технической возможности прочитать переписку игроков. Для открытых (незашифрованных) P2P-команд трафик не должен вызывать `clatd/v4-ext`. При разборе пакета проверка длины payload, состава v6-пакета, логики/PAD_ALIGN не исключает штатные наполнения.

### 2.2 Структура пакета сообщения в сети (Mobile Chat Packet Layer) — 24 байта + payload
```void
struct MobileChatPacket {
    u32 protocol_version;   // Версия сетевого протокола (0x0200)
    u32 target_group_id;    // ID гильдии или комнаты чата
    u64 message_id;         // Инкрементальный номер сообщения
    u8  iv[12];             // Вектор инициализации для шифра AES
    u32 payload_len;        // Длина зашифрованного текста payload
    char encrypted_data;    // Строковый динамический буфер: бинарное зашифрованное тело сообщения
    u32 integrity_hash;     // CRC32 хэш для проверки лимитов и корректности пакета рантаймом KINII
}
```

## 🏕️ 3. Стратегический менеджмент базы (State of Decay 2 Синергия)

Приложение позволяет игроку контролировать состояние своей укрепленной базы в открытом мире игры, даже находясь оффлайн. В соответствии с разделом `[DECISIONS.md](./DECISIONS.md)` удаленное управление отсутствует; приложение используется исключительно в режиме чтения.

1. **Мониторинг ресурсов:** Интерфейсы папки `View/` отображают текущие показатели лагеря: запасы провизии, медикаментов, прочность стен и количество патронов в турелях, считывая актуальные данные из скрытых патчей чанков `sql.core`.
2. **Push-уведомления об атаках (Осады):** Если в игре (на выделенном сервере Battlefield-типа) к базе игрока мигрирует орда монстров из-за высокого уровня шума, сервер через `deploy_hub.vc` отправляет высокоприоритетное push-уведомление на смартфон владельца базы.
3. **Удаленное командование:** Функция жестко ограничена в целях безопасности. Игрок через мобильный интерфейс может отдать только ограниченный набор команд: «Запросить рапорт» или «Активировать автоматику щитка» (если это настроено локальным физическим реле в игре). Пакет команды верифицируется цифровой подписью рантайма смартфона и мгновенно инжектируется в игровой мир через `bridge.ctos`.

## 🚨 4. Протокол безопасности и функция Fake Panic

Мобильный мессенджер содержит строгие защитные механизмы, описанные в `PLAN.md`:
* **Обнаружение Root/Отладки:** Если приложение обнаруживает, что среда Android скомпрометирована (наличие Root-прав, запущенный Frida-сервер или попытки замера памяти дампа файла макета приложения), рантайм блокирует интерфейсы.
* **Исполнение `sys.fake_panic`:** Локальная база данных истории чатов `sql.core` на смартфоне немедленно блокируется. Экран мессенджера подменяется фальшивой системной ошибкой Android (Crash-репорт), а сессионные ключи в Ghost-RAM стираются. Восстановить переписку без повторной авторизации через ПК-клиент игры становится невозможно.
* **Логирование и скрытность:** Root/Debug-сигналы могут использоваться как риск-факторы, но не дают абсолютного доказательства намерения взлома. Движок должен беззвучно ограничивать чувствительные операции, запросить повторную авторизацию, сохраняя аудит без гарантии в прозрачность логов. Полное логирование внутренней защиты и безвозвратное стирание истории обрабатываются обменом `kiniibuild/file` режима. Адрес и локация в памяти защищаются средством `pairing/recovery` процедурой. Адрес `sys.fake_panic` не входит в проводной API.
