
# 📻 Спецификация тактической голосовой связи, радиоволн и аудио-стриминга (AUDIO_COMMS_SPEC.md)

Настоящий документ определяет сетевую архитектуру, алгоритмы цифровой обработки сигналов (DSP) и протоколы шифрования для подсистемы голосовой связи (VoIP) и внутриигрового радиовещания. Подсистема объединяет в себе концепцию динамических радиостанций пустоши из **Fallout 4 / Fallout 76**, позиционный голосовой чат с учетом акустики помещений и тактические радиочастоты отрядов из **Battlefield**, а также механику привлечения монстров живым голосом игрока из **State of Decay 2**.

Главная цель данной подсистемы — обеспечить бесшовную, защищенную от прослушивания голосовую связь между игроками, находящимися внутри движка UZDoom на ПК, и участниками гильдии, подключенными к радиоволне через мобильное приложение-компаньон на Android.



## 🏗️ 1. Системные и архитектурные связи

Аудио-коммуникационный слой напрямую взаимодействует с ядром **KINII (`void.run`)** и смежными модулями проекта через систему перекрестных ссылок:
* **Шифрование голосового потока:** Ключи потокового шифрования (алгоритм ChaCha20-Poly1305) для закрытых клановых частот генерируются и хранятся исключительно в изолированной памяти Ghost-RAM через [memory.ctos](../Lang_for_my_decisions/memory.ctos).
* **Сетевой транспорт:** Передача сжатых аудио-фреймов в реальном времени без задержек (Low-Latency UDP) базируется на сокет-инжекторе `net.raw_inject` из [MULTIPLAYER_SPEC.md](./MULTIPLAYER_SPEC.md).
* **Акустический радар и стелс:** Громкий разговор или крик игрока в открытый микрофон генерирует акустические волны на радаре шума в [MAP_SPEC.md](./MAP_SPEC.md), стягивая орды монстров из соседних чанков.
* **Сводки новостей в эфире:** Динамический радио-диджей считывает историю побед кланов и захваченных баз из скрытых таблиц `HiddenVault` через [sql.core](../Lang_for_my_decisions/sql.core).
* **Мобильная рация (Walkie-Talkie Mode):** Фоновое воспроизведение радиостанций и кнопка тангенты (Push-to-Talk) на экране смартфона реализованы через [COMPANION_APP.md](./COMPANION_APP.md) и шаблоны [View/](../Lang_for_my_decisions/View/).

## 📊 2. Бинарная структура голосового пакета и радиоволны

Для минимизации сетевого трафика звук с микрофона оцифровывается с частотой дискретизации $24\text{ кГц}$, сжимается ультра-быстрым кодеком **Opus** (битрейт $24\text{ Кбит/с}$, размер окна $20\text{ мс}$) и упаковывается в строго выровненную структуру.

```
    void
    struct NetVoiceFramePacket {
        u32 magic_header;           // 0x4B564F58 ("KVOX" - Kinii Voice Frame)
        u32 sender_player_id;       // Сетевой ID говорящего игрока (или ID смартфона компаньона)
        u16 frequency_channel;      // Частота: 0x0000 = 3D Proximity, 1000..9999 = Радиочастоты (100.0 - 999.9 МГц)
        u32 sequence_number;        // Инкрементальный номер фрейма для сборки в Jitter-буфере без разрывов
        
        // Пространственные координаты говорящего (для 3D-позиционирования OpenAL в UZDoom):
        f32 speaker_pos_x;          // Координата X в чанке
        f32 speaker_pos_y;          // Координата Y в чанке
        f32 speaker_pos_z;          // Высота Z
        
        u8  voice_volume_db;        // Пиковый уровень громкости речи (в децибелах: 0..120 дБ для ИИ монстров)
        u8  encryption_flag;        // 0x00 = Открытый эфир, 0x01 = Зашифровано ключом клана (CLAN_SPEC.md)
        u16 opus_payload_len;       // Фактическая длина сжатого аудио-блока (обычно 60-80 байт)
        u8  opus_data[80];          // Зашифрованный массив аудио-данных кодека Opus
        u32 frame_crc32;            // Контрольная сумма пакета + сессионный токен из Ghost-RAM
    }

```

## 🔊 3. Три режима аудио-коммуникации и DSP-фильтры
## 🔊 3. Математическая модель 3D-звука, окклюзии стен и DSP-эффектов

Аудио-движок OpenAL внутри UZDoom в связке с DSP-процессором рантайма `void.run` обрабатывает входящий голос в трех независимых режимах:

### 3.1 Позиционный 3D-чат (Proximity Voice Chat)
### 3.1 Позиционный 3D-чат и глушение стенами (Proximity & Wall Occlusion)

* **Логика затухания:** Если `frequency_channel == 0`, голос игрока звучит непосредственно из координат его персонажа в мире игры. Громкость падает по логарифмическому закону на дистанции от $64$ до $1536$ юнитов Doom.
* **Окклюзия стенами (LineDefs Raycast):** Рантайм KINII проверяет прямую видимость между говорящим и слушателем. Если между ними находится глухая бетонная стена из [WORLD_DESIGN.md](./WORLD_DESIGN.md), к голосу применяется фильтр нижних частот (Low-Pass Filter на $400$ Гц) — голос звучит глухо, как из-за стены.
* **Акустический перехват ИИ:** Если игрок кричит в микрофон (`voice_volume_db > 75`), сервер спавнит акустический импульс в текущем чанке. Монстры слышат живую речь игрока и идут на звук.

Если пакет приходит с `frequency_channel == 0x0000`, голос воспроизводится как физический источник звука из уст модели игрока:
1. **Логарифмическое затухание:** Слышимость речи падает с расстоянием $d$. На дистанции $d \le 128$ юнитов громкость равна $100\%$, на границе чанка ($d \ge 2048$ юнитов) голос полностью растворяется в фоновом шуме ветра.
2. **Трассировка преград (LineDefs Occlusion):** Между координатами говорящего $(X_1, Y_1)$ и ушами слушателя $(X_2, Y_2)$ выпускается проверочный луч. За каждую пересеченную сплошную стену (`LineDef` с флагом `TWOSIDED == 0` из [WORLD_DESIGN.md](./WORLD_DESIGN.md)) частота среза фильтра нижних частот (Low-Pass Filter) опускается по формуле:

$$F_{cutoff} = \frac{20000\text{ Гц}}{1 + 4 \cdot N_{walls}}$$

* При $N_{walls} = 2$ (две стены между игроками) все частоты выше $2200\text{ Гц}$ обрезаются — игрок слышит лишь глухое бубнение за бетонной преградой.
* Если игрок находится под действием контузии головы из [SURVIVAL_SPEC.md](./SURVIVAL_SPEC.md), поверх голоса накладывается эффект звона в ушах (синусоида $4500\text{ Гц}$).

### 3.2 Тактическая рация (Tactical Radio Frequencies)
### 3.2 Тактические радиочастоты и Радиоперехват (Battlefield / Survival Style)

Игроки могут выставить на своей рации любую частоту от `100.0` до `999.9` МГц.
* **Открытые волны:** Любой игрок или шпион вражеского клана, случайно подобравший частоту вашей группы на своем приемнике, сможет подслушивать переговоры.
* **Крипто-волна Клана:** В [CLAN_SPEC.md](./CLAN_SPEC.md) при постройке «Радиовышки шифрования» на базе, частота клана переводится в режим `is_encrypted = 1`. Если чужак настроится на эту волну без ключа в `Ghost-RAM`, он услышит только белый шум и цифровое скрежетание.
* **DSP-эффект военной рации:** При передаче по радиоканалу рантайм накладывает полосовой фильтр (Band-Pass $300\text{ Гц} - 3000\text{ Гц}$), легкий дисторшн перегрузки и характерный звук щелчка тангенты (Roger Beep) в начале и конце фразы.

Каждый игрок имеет портативную рацию и может вручную накрутить любую частоту в диапазоне от `100.0` до `999.9` МГц:
* **Риск радиоперехвата:** Если группа выживших общается на открытой волне (например, `433.5 МГц`, `encryption_flag == 0`), любой вражеский игрок, просканировавший эфир своим приемником, услышит их переговоры и узнает, в какой чанк они везут лут.
* **Военное крипто-шифрование Клана:** Если гильдия построила «Криптографический ретранслятор» на своей базе ([CLAN_SPEC.md](./CLAN_SPEC.md)), их клановая частота получает статус `encryption_flag == 1`. Поток шифруется ключом из `Ghost-RAM`. При попытке чужака настроиться на эту волну рантайм воспроизводит ему агрессивный цифровой шум (модемный скрежет), защищая тайну переговоров.
* **Аналоговый DSP-фильтр рации:** На все радиопередачи накладывается каскад эффектов: полосовой фильтр ($350\text{ Гц} - 2800\text{ Гц}$), мягкий клиппинг (искажение при крике), характерный щелчок кнопки тангенты (`Roger Beep`) и подмешивание белого эфирного шума, если расстояние между игроками превышает $3$ чанка ($12288$ юнитов).

### 3.3 Глобальное Радио Пустоши (Fallout 4 Dynamic Radio)

Выделенный сервер транслирует потоковые радиостанции через `deploy_hub.vc`.
* **Реактивный эфир:** Скрипты радио-диджея считывают лог глобальных событий из [MAP_SPEC.md](./MAP_SPEC.md) и базу данных `sql.core`. Если клан игроков уничтожил босса в чанке `[X:4, Y:-2]` или захватил базу, между музыкальными треками в эфире звучит сгенерированная сводка новостей об этом событии.

## 📱 4. Интеграция со Смартфоном (Режим Гарнитуры и Фонового Радио)
## 📻 4. Глобальное Радио Пустоши (Fallout 4 Dynamic Broadcast)

Приложение-компаньон ([COMPANION_APP.md](./COMPANION_APP.md)) превращает реальный телефон игрока в физическую рацию:
1. **Смартфон как внешняя тангента (PTT):** Игрок может положить телефон перед собой на стол во время игры на ПК. Зажав большую кнопку «ПЕРЕДАЧА» на экране `View/`, он говорит напрямую в микрофон смартфона, не настраивая микрофон в Windows.
2. **Связь вне дома:** Офицер клана, едущий в автобусе или находящийся на работе, может подключиться к частоте своей группы со смартфона и голосом координировать оборону базы в реальном времени, глядя на тактическую карту [MAP_SPEC.md](./MAP_SPEC.md).

На выделенном сервере ([MULTIPLAYER_SPEC.md](./MULTIPLAYER_SPEC.md)) круглосуточно работают потоковые радиостанции (например, волна `101.5 МГц — Радио Убежища`).
* **Живая реакция на действия игроков:** Серверный модуль радио анализирует глобальные таблицы [sql.core](../Lang_for_my_decisions/sql.core) и события [MAP_SPEC.md](./MAP_SPEC.md). Когда музыкальный трек заканчивается, в эфир выходит предзаписанный или синтезированный голос диджея, который зачитывает реальную сводку с сервера: 
  * *«Срочные новости, выжившие! Только что клан [Название клана] отбил атаку гигантской орды в секторе [X:12, Y:-4], потеряв две турели! А на аукционе гильдий замечена редкая плазменная винтовка...»*
