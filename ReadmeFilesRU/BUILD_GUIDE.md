# 🛠️ Инструкция по сборке и развертыванию проекта (BUILD_GUIDE.md)

Этот документ содержит исчерпывающее руководство по компиляции, сборке и развертыванию гибридной экосистемы, состоящей из игрового движка **UZDoom (C++)** и защищенных системных слоев на базе языка **KINII**.

Пайплайн автоматизирован через сборочный скрипт `builder.vc` и компилятор `compiler.core`, которые объединяют игровой код и механизмы скрытности в единую рабочую среду под управлением рантайма `void.run`.

---

## 📋 1. Системные требования и зависимости

| № | Состояние системы | Важность | Описание |
|---|---|---|---|
| 1 | Репозитории (`Lang_for_my_decisions`) | Обязательно | Да, до основного репозитория. Проверка правил сборки g++ и Linux; Cmake-конфигурация присутствует. |
| 2 | Модифицированный UZDoom из исходников | Обязательно | Нет в checkout. Сначала собрать и зафиксировать целевой commit. Реализована интеграция: добавлены заголовочные файлы, адаптер и API. |
| 3 | Сборщик KINII (`compiler.core`) | Обязательно | Готовый бинарник, собран под Windows x64. |
| 4 | Android APK Компонент | Ниже | Нужен нативной проект и стандартный Android toolchain. |
| 5 | Мост (`bridge.ctos`) | Обязательно | `bridge.dll` / `.so` создаёт shared-library ABI моста. |

Для успешной сборки всех компонентов рабочая станция должна соответствовать следующим требованиям:

* **Целевые ОС:** Windows 10/11 (x64) или Android 10-15 (ARM64 для мобильного компаньона).
* **Инструментарий C++:** Microsoft Visual Studio 2022 (MSVC v143) или Clang 16+, а также CMake 3.25+.
* **Инструментарий KINII:** Установленный транслятор `compiler.core` и откомпилированный загрузчик `void_win.exe`.
* **Зависимости UZDoom:** Библиотеки Vulkan SDK / OpenGL, SDL2, OpenAL, и zlib (все они автоматически подтягиваются подсистемой CMake движка UZDoom).

Это следует за разделом `checkout` зависимостей, не нужно копировать его исходники внутрь `AlmightyDigital`. При обнаружении разницы повторить сверку API и обновить `PROJECT_STATUS.md` / `PROJECT_STATUS.v2`.

## 🏗️ 2. Пайплайн сборки (Step-by-Step Build Process)

Процесс сборки разделен на два этапа: сначала компилируются защищенные низкоуровневые модули KINII, затем собирается C++ фронтенд UZDoom, который линкуется с получившимися системными библиотеками.

```text
[Шаг 1: compiler.core] ──> Собирает kernel, memory, sql, bridge ──> bridge.dll / .so
│
▼
[Шаг 2: CMake + MSVC ] ──> Компилирует исходники UZDoom (C++)  ──> Линковка с мостом
│
▼
[Результат: Итог    ] ──> Исполняемый файл игры + Авторизованный рантайм void.run
```

Если зависимости еще не рядом с игровым проектом, из общего родительского каталога можно выполнить:
```bash
git clone https://github.com
cd Lang_for_my_decisions && git checkout dev-core
# Ожидаемая структура каталогов:
# [Родитель]
#  ├── Lang_for_my_decisions (compiler.core)
#  └── AlmightyDigital (текущий проект)
```

### Шаг 1: Сборка «Kinii» smart linker
Требования из `compiler/CmakeLists.txt` и исходников:
* `Cmake >= 3.25+`
* Компилятор C++20: GCC/Clang или MSVC с поддержкой используемых конструкций.
* Ninja — не обязательный, но рекомендуемый зависимостью инструмент.

Команды из родительского каталога, содержащего `Lang_for_my_decisions`:
```bash
cmake -S Lang_for_my_decisions/compiler -B build/kinii -DCMAKE_BUILD_TYPE=Release
cmake --build build/kinii --config Release
```

### Шаг 2: Конфигурация Оборудования (HWID Binding)
Перед компиляцией системных слоев необходимо жестко привязать проект к целевому оборудованию разработчика или тестового стенда. Это предотвращает запуск зашифрованных сетевых функций на несанкционированных машинах.
1. Откройте главный конфигурационный файл `main.vc`.
2. Найдите параметр `MASTER_HWID` и скорректируйте его под сигнатуру вашего процессора/BIOS (например, для тестовой станции Dell или Android-смартфона).
3. Для приложения гарантированный результат сборки находится в `build/win/bin/release/uzdoom.exe`. Для Visual Studio — в аналогичной конфигурации, например `build/win/bin/release/uzdoom.exe`.

Проверка CLI и штатных примеров:
```bash
# Вызов скомпилированного сборщика KINII
./build/kinii/kinii --version
# Запуск сборщика ядра и сетевого моста в скрытом режиме
./build/kinii/kinii check Lang_for_my_decisions/examples
```
*Этот шаг компилирует файлы `kernel.ctos`, `memory.ctos` (Ghost-RAM), `sql.core` (HiddenVault) и `bridge.ctos` в единую динамическую библиотеку моста, защищенную от реверс-инжиниринга.*

### Шаг 3: Сборка игрового движка UZDoom
После того как мост готов, собирается сам игровой движок, который подхватит скомпилированные функции:
```bash
# Инициализация и генерация файлов проекта через CMake
cmake -B build/uzdoom -DCMAKE_BUILD_TYPE=Release -DKINII_INTEGRATION=ON -DKINII_COMPILER_PATH=build/kinii/src/ -D ... /main.kinii

# Компиляция бинарников игры
cmake --build build/uzdoom --config Release
```
Последняя команда завершает установку. Это проверка инструментария хоста, объект сборки игры, а не подтверждение кросс-сборки Windows/Android. Путь `/src/` в примере относится к MSVC-секции, но `kiniibuild` использует подходящий остаток и расширение `.exe`. Обратите внимание, что это не является командой сборки ядра.

### 4. Компиляция и развертывание игры
```bash
cmake --build build --config Release
# Сокращенная команда из старой инструкции удалена (не поддерживается одновременно 'kiniibuild')
# Убедитесь, что пути соответствуют вашему CMakeLists.txt
```

## 📱 3. Сборка мобильного компаньона (Android Deployment)

**ПК Подсистема/iOS:** Файлы ядра компилируются в нативную библиотеку и кладутся в папку `kernel.ctos`, а не в `main.vc`, а не нужен для `Kinii smart compiler`. Установленный ID не является секретом или заменой аутентификации.

Для того чтобы развернуть сетевой мессенджер гильдии на смартфоне, используется конфигурация из файла `deploy_hub.vc`:

### Пайплайн мобильного развертывания:
1. Подключите Android-устройство (версии 10-15) в режиме отладки по USB.
2. Запустите сборку нативного мобильного узла:
   ```bash
   void_win.exe deploy_hub.vc --platform=android --arch=arm64
   ```
3. Скрипт упакует рантайм `void.run`, сетевые интерфейсы мессенджера из папки `View/` и скомпилирует нативный `.apk` файл, автоматически установив его на смартфон. Этот раздел — план, не тестируемый в автоматическом конвейере.

### Дальнейшие шаги тестирования:
* Зафиксировать исходники и базовый UZDoom, собрать baseline без интеграции.
* Добавить маленький флаг авторизации в макетную адаптер-сборку.
* Реализовать и протестировать С-ABI/Handshake; проверить падение при несовместимости версий, портов и кодов ошибок.
* Подключить Ghost-RAM, проверить буферы.
* Подключить защищённую сеть, затем мобильный узел.
* Измерить производительность и задержки; тесты памяти часто симуляции и вызова команд.

## 🚨 4. Верификация запуска и тестирование защиты

### Критерии приемки (IMPLEMENTATION BENCHMARK / IMPLEMENTATION ROADSHEET):
* Границы тестов: `BRIDGE_SPEC.md` / `IMPLEMENTATION_SPEC.md`.

После сборки в корневом каталоге проекта появится финальный исполняемый файл игры. При первом запуске рантайм `void.run` выполняет автоматическую самодиагностику:

1. **«Проверка целостности»**: Движок сверяет цифровые подписи файлов `firmware.ctos` и `runtime.ctos`. Если файлы изменены сторонними программами — запуск блокируется.
2. **«Инициализация моста»**: При фиксации запуска KINII проверяет `MASTER_HWID` компьютера. В консоли UZDoom (вызывается на `~`) должна появиться строка: 
   `"Status: KINII Secure Core active. Ghost-RAM allocated successfully."`
3. **«Тест отладки (Анти-дамп)»**: Если во время игры попытаться подключить к процессу сторонний дебаггер (например, CheatEngine или x64dbg), сработает триггер безопасности из `PLAN.md` — игра сымитирует критический сбой системы (`sys.fake_panic`), мгновенно затерев буферы чата в Ghost-RAM нулями, предотвращая утечку переписки, и закроет сетевые порты чата.

До полноценного игрового пайплайна можно проверить согласованность документации из ядра этого репозитория:
```bash
python3 tools/check_docs.py
python3 -m unittest discover -s tests -p "test_*.py"
```

Не ожидайте строку `"Status: KINII Secure Core active"` от немодифицированного UZDoom, какой интегрирован пока нет. Сообщение об успешной проверке `kinii` также не означает, что Ghost-RAM, HiddenVault, E2EE или аварийное развертывание уже запущены на сервере.

Команды установки на телефон будут добавлены только после появления стабильного собираемого проекта. Сырая прошивка устройства, обход ADB или запись в скрытые сектора eMMC не являются частями нормального деплоймента приложения.
