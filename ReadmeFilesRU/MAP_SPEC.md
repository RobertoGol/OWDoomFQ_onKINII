# 🗺️ Спецификация глобальной интерактивной карты и динамических событий (MAP_SPEC.md)

Настоящий документ содержит исчерпывающее техническое и архитектурное описание подсистемы интерактивной карты, позиционирования объектов в реальном времени и движка генерации динамических глобальных событий (ивентов). Система спроектирована на базе интеграции трех игровых концепций: выносного тактического планшета / Pip-Boy из **Fallout 4 / Fallout 76**, системы акустического привлечения и миграции орд монстров из **State of Decay 2**, а также масштабируемых серверных сценариев ивентов из **Battlefield**.

Главная цель данной подсистемы — предоставить игроку полноценный «второй экран» на мобильном устройстве, разгрузив игровой интерфейс (HUD) на ПК, и обеспечить динамическое изменение геймплейного наполнения открытого мира под управлением рантайма KINII.

## 🏗️ 1. Системные и архитектурные ссылки

Подсистема глобальной карты является основным координатором пространственных данных в экосистеме проекта:
* **Пространственная разметка:** Координатная сетка и правила подгрузки зон полностью опираются на математическую модель чанков, зафиксированную в [WORLD_DESIGN.md](./WORLD_DESIGN.md).
* **Сетевой стриминг координат:** Высокоскоростная передача пакетов позиционирования игроков и монстров по UDP-каналам регламентируется в [MULTIPLAYER_SPEC.md](./MULTIPLAYER_SPEC.md).
* **Сейвы состояния ивентов:** Данные об уничтоженных или зачищенных точках интереса (POI) пишутся в скрытые сектора HiddenVault через движок данных [sql.core](../Lang_for_my_decisions/sql.core).
* **Мобильный вывод:** Векторный рендеринг карты мира и обработка push-уведомлений на Android описаны в спецификации мобильного компаньона [COMPANION_APP.md](./COMPANION_APP.md).
* **Визуальные ассеты:** Схемы интерфейса карты, иконки маркеров и радарные сетки хранятся в папке интерфейсов [View/](../Lang_for_my_decisions/View/).

## 📊 2. Бинарные структуры пространственных данных (GPS & Event Packets)

Для обеспечения плавной отрисовки маркеров на смартфоне без задержек, координатные данные пакуются в минималистичные структуры и передаются асинхронными потоками.

### 2.1 Пакет телеметрии объекта (Entity Telemetry Packet) - 16 байт
```void
struct EntityTelemetry {
    u32 entity_id;          // Уникальный ID сущности (Игрок, Монстр, Турель, Выпавший лут)
    u8  entity_type;        // Тип объекта (0x01 = союзник, 0x02 = враг, 0x03 = POI)
    f32 pos_x;              // Абсолютная координата X в мире Doom
    f32 pos_y;              // Absolute координата Y в мире Doom
    u8  status_flags;       // Состояние (бит #0: в бою, бит #1: ранен, бит #2: мертв)
}
```

### 2.2 Пакет глобального события (Global Event Packet) - 64 байта
```void
struct GlobalEvent {
    u32 event_id;           // Уникальный идентификатор активного ивента
    u8  event_type;         // Тип (0x01 = падение спутника, 0x02 = осада базы, 0x03 = босс-рейд)
    i32 target_chunk_x;     // Индекс чанка X, где разворачивается событие
    i32 target_chunk_y;     // Индекс чанка Y, где разворачивается событие
    u32 duration_seconds;   // Таймер обратного отсчета до завершения события
    u32 reward_pool_id;     // Ссылка на таблицу лута в world_stream.void
    char event_title;    // Строковое название события для вывода в View/ (32 байта)
}
```

## ⚡ 3. Математика Движка Живой Карты и Акустический Радар Шума

Интерактивная карта выполняет роль выносного тактического планшета. Игрок видит на экране смартфона перемещения объектов в реальном времени.

### 3.1 Алгоритм трансляции координат на «Второй экран»
1. Каждые 3 тика (примерно 35 миллисекунд) сервер игры собирает массив структур `EntityTelemetry` для всех объектов в активном радиусе игрока.
2. Сетевой мост [bridge.ctos](../Lang_for_my_decisions/bridge.ctos) перехватывает массив, шифрует его временным сессионным ключом из Ghost-RAM и пересылает на мобильный рантайм `void.run`.
3. Мобильное приложение переводит координаты Doom в пиксели экрана смартфона на основе формул скейлинга чанков из [WORLD_DESIGN.md](./WORLD_DESIGN.md) и мгновенно перерисовывает векторный слой интерфейса из папки [View/](../Lang_for_my_decisions/View/).

### 3.2 Математическая модель Радара Шума (State of Decay 2 Акустика)
Каждый выстрел или взрыв внутри игрового движка UZDoom генерирует акустический импульс, регистрируемый рантаймом KINII. 

Интенсивность шума $I$ в точке пространства падает обратно пропорционально квадрату расстояния $d$ от источника звука:

$$I = \frac{I_0}{d^2}$$

Где $I_0$ — базовый коэффициент громкости оружия (описан в спецификации открытого мира).
* **Отображение на карте:** Мобильное приложение накладывает на векторную карту полупрозрачные красные круги, визуализирующие зоны высокого акустического загрязнения.
* **Поведение ИИ (Монстров):** Выделенный сервер считывает матрицу шума. Если суммарная интенсивность $\sum I$ в чанке превышает критический порог, скрипты `world_stream.void` отдают команду фоновым ордам монстров начать миграцию в чанк игрока. Игрок видит на экране смартфона, как маркеры орд начинают стягиваться к его позиции.

## 🚨 4. Движок Глобальных Событий и Push-Оповещения

Выделенный сервер мультиплеера ([MULTIPLAYER_SPEC.md](./MULTIPLAYER_SPEC.md)) работает в циклическом режиме генерации динамических сценариев, чтобы поддерживать персистентность и интерес к исследованию мира.

```

    [ Выделенный Сервер игры ] ──(Инициация события)──> [ deploy_hub.vc (Хаб) ]
            │
    (Генерация Push пакета)
            │
            ▼
    [ Android-Смартфон Игрока ] <──(Вывод POI на карту)── [ COMPANION_APP.md ]

```


### 4.1 Протокол информирования об Ивентах (Event Notification Protocol)
1. Каждые 30 минут сервер вызывает процедуру `event.tick_generator()`. На основе системного сида выбирается случайный тип события, например «Падение военного спутника» (`event_type: 0x01`).
2. В целевом чанке изменяется матрица спавна предметов в [INVENTORY_SPEC.md](./INVENTORY_SPEC.md): сундукам присваивается класс `RARITY_LEGENDARY`.
3. Структура `GlobalEvent` отправляется на бэкенд-хаб `deploy_hub.vc`.
4. Хаб генерирует высокоприоритетное push-уведомление. Даже если у игрока закрыто приложение и выключен ПК, на смартфоне срабатывает оповещение: *«🚨 Внимание согильдийцам! В чанке [X:5, Y:-2] зафиксировано падение спутника корпорации. Время на зачистку: 45 минут»*.
5. При клике на уведомление открывается приложение [COMPANION_APP.md](./COMPANION_APP.md), активируется визуальный слой карты, и на сетке чанков загорается пульсирующий маркер POI, позволяя игроку координировать действия клана из [CLAN_SPEC.md](./CLAN_SPEC.md) еще до запуска игры на ПК.
