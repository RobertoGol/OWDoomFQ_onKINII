# 🖥️ Спецификация подсистемы браузера серверов и мастер-листинга (SERVER_BROWSER_SPEC.md)

Статус: **целевой дизайн, не реализованная подсистема**. Общая сверка: [PROJECT_STATUS.md](./PROJECT_STATUS.md) / [PROJECT_STATUS.v2](./PROJECT_STATUS.v2); размеры схем: [SERIALIZATION_SPEC.md](./SERIALIZATION_SPEC.md) / [SERIALIZATION_SPEC.v2](./SERIALIZATION_SPEC.v2) (готовые листинги не считаются утвержденными без записи в `sql.core` и `memory.ctos` / `DECISIONS.md`).

Настоящий документ определяет архитектуру, сетевые протоколы и логику работы браузера серверов (Server Browser). Подсистема отвечает за обнаружение, фильтрацию, опрос (Query) и подключение к игровым сессиям. Архитектура объединяет в себе систему мгновенного поиска локальных комнат (**LAN**), списки быстрого подключения к друзьям по P2P-инвайтам (**Borderlands 2**) и глобальный Мастер-Сервер со списками выделенных серверов (**Battlefield / Fallout 76**).

Уникальной особенностью системы является **двойное присутствие**: браузер серверов доступен как внутри игрового движка UZDoom на ПК, так и удаленно через мобильное приложение-компаньон.

---

## 🏗️ 1. Системные и архитектурные связи

Подсистема поиска серверов является шлюзом инициализации сетевой сессии и завязана на следующие модули:
* **Сетевые сокеты:** Низкоуровневый обмен пакетами опроса и пробитие NAT настраиваются по правилам из [MULTIPLAYER_SPEC.md](./MULTIPLAYER_SPEC.md).
* **Конфигурация хаба:** Логика регистрации выделенных серверов на центральном Мастер-Сервере прописана в [deploy_hub.vc](../Lang_for_my_decisions/deploy_hub.vc) (ссылка на ветку: [://github.com](https://://github.com)).
* **Мобильный интерфейс:** Визуальное отображение списка серверов и пинга на Android обрабатывается шаблонами из папки [View/](../Lang_for_my_decisions/View/) (ссылка на ветку: [://github.com](https://://github.com)).
* **Синхронизация профилей:** При подключении к серверу происходит валидация рангов и клановых тегов игрока, описанная в [CLAN_SPEC.md](./CLAN_SPEC.md).

## 🛰️ 2. Механизмы сбора информации о серверах (Discovery Protocols)

Браузер собирает данные из трех независимых источников в зависимости от выбранной вкладки интерфейса:

```text
            ┌─────────────── БРАУЗЕР СЕРВЕРОВ ───────────────┐
            │                                                │
            ▼                                                ▼
[ Глобальный Мастер-Лист ]                      [ Локальный LAN-сканер ]
(Запрос к веб-API deploy_hub.vc)               (Сырой UDP-бродкаст на порт 5029)
            │                                                │
            ▼                                                ▼
Выделенные сервера Battlefield                   Локальные сессии в подсети
```

При команде на вкладку «Локальная сеть» рантайм `void.run` открывает сокет и отправляет асимметричный UDP-запрос `NET_REQ_LAN_INFO` на широковещательный адрес подсети. Все запущенные в LAN-моде хосты, поймав этот пакет, отправляют обратно пакет метаданных (см. структуру ниже). Время ожидания ответа (Timeout) составляет 1500мс.

### 2.1 Локальное сканирование (LAN Discovery)
Клиент UZDoom отправляет сырой широковещательный UDP-пакет на порт `5029` в локальную подсеть. Хост возвращает структуру метаданных сервера (Имя, текущий чанк открытого мира, количество игроков).

### 2.2 Глобальный Мастер-Сервер (Master Server Listing)
Выделенные сервера (Dedicated) при запуске регистрируются на центральном Мастер-Сервере, адрес которого жестко зашит в `runtime.ctos`.
1. Клиент делает легкий HTTPS-запрос к API `deploy_hub.vc`.
2. Мастер-сервер возвращает компактный JSON-массив, содержащий только IP-адреса и порты активных серверов.
3. Получив список IP, клиент UZDoom начинает параллельный многопоточный опрос (Ping/Query) каждого сервера напрямую по UDP для вычисления актуального пинга.

### 2.3 Система P2P Лобби друзей (Borderlands 2 Co-op)
Если игрок хочет подключиться к другу, мессенджер в [COMPANION_APP.md](./COMPANION_APP.md) запрашивает статус друга. Если друг является хостом Listen-сервера, сигнальный сервер передает его временный STUN-токен напрямую клиенту. Браузер серверов инициирует автоматический пробой NAT через инжектор `net.raw_inject` без вывода сервера в общий глобальный список.

## 📦 3. Бинарная структура пакетов опроса (Server Query Layer)

Для минимизации сетевого трафика и защиты сервера от DDOS-атак пакетами опроса, структуры данных жестко лимитированы по размеру; структуры данных жестко лимитированы по размеру.

### 3.1 Пакет ответа сервера (Server Info Packet) — 92 байта packed / 96 байта native x64
Когда клиент пингует сервер, хост возвращает следующий бинарный блок данных, приходящий в «битых» сегментах:
```void
struct NetServerInfoPacket {
    u32 magic_bytes;        // 0x4B494E51 ("KINQ" - Kinii Query)
    u16 server_port;        // Игровой порт хоста
    u8  current_players;    // Текущее количество игроков на сервере
    u8  max_players;        // Максимальный лимит слотов (например, 64)
    i32 current_chunk_x;    // Координата X центрального чанка, где сейчас экшен
    i32 current_chunk_y;    // Координата Y центрального чанка, где сейчас экшен
    u8  is_password_set;    // Флаг приватности (0x00 = открытый, 0x01 = нужен пароль)
    u8  _padding;           // Выравнивание структуры
    u16 server_flags;       // Бит #0: Разрешен ли ПВП, Бит #1: Хардкор-мод
    char server_name[32];   // Название сервера в UTF-8 (строго 32 байта)
    char current_map[32];   // Имя мастер-сценария открытого мира (строго 32 байта)
}
```
Когда клиент пингует сервер, хост возвращает бинарный блок данных. Когда игрок заходит на сервер, движок разворачивает бинарный блок данных.

## 📱 4. Удаленный мониторинг серверов со смартфона

Поскольку подсистема интегрирована с мобильным компаньоном [COMPANION_APP.md](./COMPANION_APP.md), игроку доступен расширенный функционал управления сессиями.

1. **Просмотр статуса без запуска игры:** Открыв приложение на Android, пользователь видит живой список выделенных серверов гильдии ([CLAN_SPEC.md](./CLAN_SPEC.md)). Визуальный слой `View/` отображает, сколько согильдийцев сейчас онлайн, в каких чанках открытого мира ([WORLD_DESIGN.md](./WORLD_DESIGN.md)) они ведут бой и насколько защищена их база.
2. **Удаленное бронирование слота (Slot Reservation):** Если выделенный сервер Battlefield-масштаба заполнен (64/64), офицер или VIP-член клана может со смартфона отправить пакет авторизации, подписанный его `MASTER_HWID`. Офицер или VIP-член клана может со смартфона отправить пакет авторизации, подписанный ключом авторизованного устройства. HWID сам по себе не является секретом. Сервер верифицирует подпись и резервирует для игрока скрытый VIP-слот. Когда игрок включит ПК и запустит UZDoom, браузер серверов мгновенно пропустит его вне очереди.
