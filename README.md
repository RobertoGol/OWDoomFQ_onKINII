# 🌌 Next-Gen Open World Doom Engine Project (Project Cross-Over)

Амбициозный проект по глубокой модернизации и рефакторингу классического движка **id Tech 1** (на базе современного исходного кода [UZDoom](https://github.com)). 

Цель проекта — полностью переписать старую DOS-архитектуру под стандарты современных игр с открытым миром, объединив лучшие механики из **Fallout 4** (исследование и строительство), **State of Decay 2** (выживание и менеджмент ресурсов), **Borderlands 2** (динамический мультиплеер и оптимизация сетевого кода) и **Battlefield** (масштабные выделенные сервера).

---

## 🏗️ Архитектура Системы и Связь с Экосистемой KINII

Проект работает в тесной интеграции с низкоуровневой системной экосистемой решения языка **KINII** (Next-Gen Solution Language). Вместо стандартных тяжелых C++ библиотек, критически важные подсистемы безопасности, стриминга памяти и криптографии вынесены в рантайм `void.run`.

Ниже приведена карта взаимодействия игрового движка с модулями ядра KINII:

## 🛠️ Основные Технологические Слои (Связи файлов репозитория)

### 1. Динамический Стриминг Открытого Мира (World Chunks)
Оригинальный Doom 2 использовал статичные BSP-деревья и ограничивал размеры карт. Наша подсистема делит мир на динамические чанки (сетка 4096х4096 юнитов). Подгрузка геометрии, стен и LineDefs происходит на лету в фоновом потоке, основываясь на координатах игрока.
* 🔗 **Логика стриминга и генерации лута:** Описана в скрипте мира [world_stream.void](./world_stream.void).
* 🔗 **Управление памятью секторов:** Выделение зон под геометрию чанков контролируется на низком уровне через Ghost-RAM в файле ядра [memory.ctos](../Lang_for_my_decisions/memory.ctos).

### 2. Сетевой Код и Быстрое Подключение (а-ля Borderlands 2)
Мультиплеер поддерживает как режим быстрого кооперативного подключения Peer-to-Peer (хост-клиент), так и работу через консольный выделенный сервер (Dedicated Server) без графической оболочки для масштабных сессий.
* 🔗 **Мост игрового чата и авторизации:** Реализован в интерфейсном слое [bridge.ctos](../Lang_for_my_decisions/bridge.ctos).
* 🔗 **Консольный логгер сервера:** Безопасное сохранение состояния мира и истории чата в скрытые сектора HiddenVault прописано в модуле данных [sql.core](../Lang_for_my_decisions/sql.core).

### 3. Экосистема: Зашифрованное Приложение-Компаньон (Мессенджер)
Игровой гильд-чат, групповые диалоги и профили игроков дублируются в мобильное приложение для Android 10-15 (ARM64). Трафик мессенджера защищен сквозным шифрованием (E2EE), развернутым прямо внутри изолированного рантайма.
* 🔗 **Конфигурация деплоя мобильного хаба:** Документация по сборке сетевого узла чата находится в [deploy_hub.vc](../Lang_for_my_decisions/deploy_hub.vc).
* 🔗 **Интерфейсы мессенджера:** Схемы управления визуальными веб-элементами чата лежат в папке управления интерфейсом [View/](../Lang_for_my_decisions/View/).

## 🚨 Безопасность и Отказоустойчивость

Поскольку проект подразумевает постоянный обмен данными между игроками и внешними приложениями, в него интегрированы защитные механизмы ядра KINII:
1. **Проверка железа:** Перед инициализацией сетевого моста проверяется параметр `MASTER_HWID` [main.vc](../Lang_for_my_decisions/main.vc).
2. **Экстренный режим:** При фиксации попыток перехвата трафика чата или дампинга памяти Ghost-RAM, срабатывает защитный протокол имитации паники, описанный в манифесте [PLAN.md](../Lang_for_my_decisions/PLAN.md).
